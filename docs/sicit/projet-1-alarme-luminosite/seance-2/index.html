💻 Séance 2 — Programmer, mesurer, régler le seuil

Lecture analogique, campagne de mesures dans trois éclairements, choix du seuil, servo, LED clignotante et bouton anti-rebond : ton alarme fonctionne pour de vrai.

🎯
Objectifs

À la fin de cette séance, je suis capable de :

  • câbler le montage sur breadboard à partir du schéma et le faire vérifier avant la mise sous tension ;
  • lire une entrée analogique avec Arduino et afficher les valeurs au moniteur série ;
  • réaliser une campagne de mesures (trois conditions, trois mesures, moyenne, dispersion) et en déduire un seuil justifié ;
  • programmer la décision (seuil), la commande du servo et de la LED, et la lecture d'un bouton sur front avec anti-rebond ;
  • valider le fonctionnement avec un protocole de tests et noter les résultats.
💾 Tes réponses sont enregistrées automatiquement sur cet appareil.

🎯 Objectif

Aujourd'hui, ton schéma devient un montage réel et un programme. Tu travailles aux PC en U, par îlot, avec la boîte de composants : pas de zone machines. Deux temps : d'abord mesurer ce que « voit » vraiment le photo-résistor dans trois situations, ensuite programmer l'alarme complète (seuil, servo, LED, bouton anti-rebond) et la tester selon un protocole.

Rôles : l'opérateur CFAO est au clavier (Arduino IDE), le magasinier câble sur la breadboard, le contrôleur qualité relit chaque fil avant l'USB et remplit les tableaux, le chef d'atelier tient le temps et fait tourner la souris (chacun doit avoir tapé du code).

🕹️ Déroulé

Étape 1 — Câbler et vérifier (0–7 min)

  1. Le magasinier réalise sur la breadboard les 4 sous-montages de la séance 1 : LDR + 10 kΩ sur A0, LED + 220 Ω sur D8, servo sur D9, bouton + 10 kΩ de tirage sur D2.
  2. Le contrôleur qualité vérifie chaque fil avec le schéma, puis : aucun fil direct entre 5 V et GND (court-circuit), LED dans le bon sens (patte longue côté résistance), rouge du servo sur 5 V.
  3. Seulement ensuite, l'opérateur branche l'USB. Si la carte s'éteint ou chauffe : débranche immédiatement et appelle le professeur.

Étape 2 — Programme 1 : lire et afficher (7–17 min)

Dans Arduino IDE, tape ce premier programme, téléverse-le, puis ouvre le moniteur série (loupe en haut à droite, vitesse 9600).

const int brocheLDR = A0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int valeur = analogRead(brocheLDR);
  Serial.println(valeur);
  delay(200);
}
  • analogRead(A0) lit la tension sur A0 et renvoie un entier de 0 (0 V) à 1023 (5 V).
  • Serial.println envoie la valeur au PC pour que tu la voies.
  • delay(200) attend 200 ms : cinq mesures par seconde.

Passe la main au-dessus de la LDR : les nombres bougent ? Le montage est bon. Sinon, retour au contrôleur.

Étape 3 — Campagne de mesures (17–29 min)

Une mesure unique ne vaut rien : trois mesures par condition, puis la moyenne. Les trois conditions reproduisent la vie de la malle :

Condition Comment la réaliser
Obscurité (malle fermée) boîte à chaussures retournée sur le montage, couvercle bien fermé
Lumière de la salle (malle ouverte) montage à découvert sur la table, éclairage habituel
Lampe (torche du téléphone à 10 cm) pire cas : quelqu'un éclaire directement l'intérieur

Question A. Les valeurs augmentent-elles ou diminuent-elles avec la lumière ? Est-ce cohérent avec ta prévision de la question E de la séance 1 (pont diviseur, LDR côté 5 V) ?

Question B. Dans une même condition, les trois valeurs sont-elles identiques ? De combien varient-elles ? D'où vient cette dispersion (ombre de ta main, néon, personne qui passe…) ?

Étape 4 — Choisir le seuil (29–35 min)

L'alarme doit distinguer malle fermée (obscurité) et ouverte (lumière de la salle). Le seuil se place entre ces deux moyennes, le plus loin possible des deux, pour que la dispersion de la question B ne fasse pas basculer l'alarme par erreur. Règle simple : seuil = (moyenne obscurité + moyenne lumière de la salle) ÷ 2.

Question C. Calcule ton seuil et justifie-le en une phrase. Puis explique ce qui se passerait avec un seuil choisi 20 unités au-dessus de la valeur « obscurité ».

Étape 5 — Programme 2 : l'alarme complète (35–47 min)

Remplace le programme 1 par celui-ci. Écris ton seuil à la place de 400 et choisis le sens de l'alerte.

#include <Servo.h>

const int brocheLDR    = A0;
const int brocheLED    = 8;
const int brocheServo  = 9;
const int brocheBouton = 2;

const int  seuil         = 400;   // TA valeur calculée à l'étape 4
const bool alerteSiClair = true;  // true : alerte quand la lumière apparaît
                                  // false : alerte quand la lumière disparaît

Servo drapeau;
bool alarmeArmee = false;
bool boutonAvant = LOW;

void setup() {
  pinMode(brocheLED, OUTPUT);
  pinMode(brocheBouton, INPUT);
  drapeau.attach(brocheServo);
  drapeau.write(0);
  Serial.begin(9600);
}

void loop() {
  // 1. Le bouton : on réagit seulement au passage relâché -> appuyé
  bool bouton = digitalRead(brocheBouton);
  if (bouton == HIGH && boutonAvant == LOW) {
    alarmeArmee = !alarmeArmee;   // bascule armée / désarmée
    delay(50);                    // anti-rebond
  }
  boutonAvant = bouton;

  // 2. Le capteur et la décision
  int valeur = analogRead(brocheLDR);
  bool lumiere = (valeur > seuil);
  bool alerte  = alarmeArmee && (lumiere == alerteSiClair);

  // 3. Les actionneurs
  if (alerte) {
    drapeau.write(90);
    digitalWrite(brocheLED, HIGH);
    delay(100);
    digitalWrite(brocheLED, LOW);
    delay(100);
  } else {
    drapeau.write(0);
    digitalWrite(brocheLED, LOW);
  }
  Serial.println(valeur);
}

Lis le programme avec ton îlot avant de le téléverser. Trois idées :

  • Le seuil : valeur > seuil donne vrai ou faux ; c'est la règle « SI… ALORS » du jeu d'introduction.
  • Le front montant : on ne bascule que quand le bouton passe de LOW à HIGH (bouton == HIGH && boutonAvant == LOW). Sinon, doigt appuyé, l'alarme s'armerait et se désarmerait des centaines de fois par seconde.
  • L'anti-rebond : un contact mécanique rebondit pendant quelques millisecondes et la carte voit plusieurs appuis. Le delay(50) les ignore.

Question D. À quoi sert la variable boutonAvant ? Que se passerait-il si on l'enlevait et qu'on écrivait simplement if (bouton == HIGH) ?

Question E. Ligne bool alerte = alarmeArmee && (lumiere == alerteSiClair); — explique dans quel cas exactement alerte vaut vrai quand alerteSiClair est false. Quel usage de l'alarme cela permet-il ?

Étape 6 — Protocole de tests (47–52 min)

Le contrôleur qualité réalise dans l'ordre les actions du tableau et note l'observé en face de l'attendu. Un test raté n'est pas un échec : c'est une information.

Action Attendu
Branchement, alarme non armée, boîte ouverte drapeau baissé, LED éteinte
Un appui sur le bouton alarme armée : boîte ouverte → drapeau levé, LED clignote
Boîte fermée sur le montage drapeau baissé, LED éteinte
Boîte rouverte drapeau levé, LED clignote
Un appui sur le bouton désarmée : plus rien ne bouge même boîte ouverte
Appui long de 3 secondes une seule bascule, pas plusieurs

Question F. Pose une main à demi au-dessus de la LDR pour obtenir une valeur proche du seuil. Que fait le servo ? Note précisément ce que tu observes : c'est le point de départ de l'analyse critique de la séance 3.

Étape 7 — Rangement et bilan (52–55 min)

Le magasinier débranche l'USB avant de toucher au montage, puis range les composants. L'opérateur enregistre le programme sous alarme-ILOT-n.ino.

🧠 Ce qu'il faut retenir

  • analogRead renvoie un nombre de 0 à 1023 proportionnel à la tension sur l'entrée.
  • Une campagne de mesures = plusieurs mesures par condition, une moyenne, une estimation de la dispersion.
  • Le seuil se place entre les deux états à distinguer, le plus loin possible des deux.
  • Un bouton se lit sur un front (changement d'état) et se protège par un anti-rebond.
  • Un programme Arduino suit la chaîne d'information : acquérir (analogRead, digitalRead) → traiter (if) → communiquer (digitalWrite, servo.write).

✅ Bilan

En trois lignes : mon seuil, comment je l'ai choisi, et le test qui a le moins bien marché (et pourquoi, selon moi).
